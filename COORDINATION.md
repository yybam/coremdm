read it before you start, and update it when you take or finish an area.

## Canonical branch: `main`

- **`main` is the single source of truth.** The live site (coremdm.web.app) and
  every CI workflow (`deploy-hosting`, `build-apk`, `deploy-firestore`) trigger off
  `main`. Do all work here.
- **`master` is stale.** It branched from an old base (`909f2cf`) and, as of
  2026-10-08, diverged hard: merging it into `main` as-is would delete the current
  multi-page site (console.html, install.html, features/faq/about/terms/privacy/
  consent/demo, style.css, app.js, qr.js) and regress the app version. **Do not
  fast-forward or merge `master` into `main`** without an explicit, reviewed
  cherry-pick of only the wanted pieces.

## Rules (both sessions)

1. Work on `main`. Don't start parallel tracks on other branches.
2. `git pull --rebase origin main` before every push. **Never force-push** a shared
   branch.
3. Before a large edit, add a line under "Live ownership" below naming the files you
   are touching, so we don't edit the same file at once.
4. App version lives only in `app/build.gradle.kts`. Never lower `versionCode` /
   `versionName`. Current: **0.4.4 (versionCode 42)**.
5. Releases: push a `vX.Y.Z` tag to build+publish the APK. Hosting redeploys on any
   push that touches `public/**`, `firebase.json`, or `.firebaserc`.
6. Don't commit large binaries to the repo. The installer's APK is pulled from the
   GitHub release at deploy time (`public/coremdm.apk.bin`, generated by CI) — not
   committed.
